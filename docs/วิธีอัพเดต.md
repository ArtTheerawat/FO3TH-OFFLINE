# วิธีอัพเดต Launcher ให้ผู้เล่น (คู่มือสำหรับเจ้าของเซิร์ฟ)

ระบบอัพเดตของ launcher ทำงานอัตโนมัติฝั่งผู้เล่น:
ทุกครั้งที่ผู้เล่นเปิด launcher จะเช็ค GitHub Releases ของ `ArtTheerawat/FO3TH-OFFLINE`
ถ้ามีเวอร์ชันสูงกว่าที่ตัว launcher ถืออยู่ → แจ้งเตือนและดาวน์โหลด-ติดตั้งให้เอง

## ขั้นตอนอัพเดต (3 ขั้น)

### 1. แก้โค้ด + ขยับเลขเวอร์ชัน
แก้ไฟล์ `launcher/launcher_core/config.py` บรรทัด `'version': '1.0.0'`
เพิ่มเลขให้สูงขึ้น เช่น `1.0.1`, `1.1.0`

> ระบบเทียบเวอร์ชันแบบตัวเลข 3 ชุด (major.minor.patch) — ตัวใหม่ต้องสูงกว่าเดิมเสมอ

### 2. Build EXE ใหม่
ดับเบิลคลิก `build_launcher.bat` → ได้ไฟล์ `dist/FO3TH_Launcher.exe`

### 3. อัพโหลดขึ้น GitHub Releases
1. ไปที่ https://github.com/ArtTheerawat/FO3TH-OFFLINE/releases
2. กด **"Create a new release"**
3. ตั้ง **Tag** = `v1.0.1` (ต้องขึ้นต้นด้วย v แล้วตามด้วยเลขเดียวกับใน config.py)
4. ใส่หัวข้อ + รายละเอียดว่าอัพเดตอะไร
5. ลากไฟล์ `FO3TH_Launcher.exe` ไปช่องแนบไฟล์
6. กด **"Publish release"**

เท่านี้ ผู้เล่นทุกคนที่เปิด launcher ตัวเก่าจะเห็นแจ้งเตือนและกดอัพเดตเองได้

## รูปแบบไฟล์ที่ระบบรองรับ

ระบบอัพเดตเดิมรองรับ 2 แบบ:
- **ไฟล์ .exe ตรง ๆ** (ชื่อ FO3TH_Launcher.exe หรือมีคำว่า setup) → ระบบปิด launcher เก่า รันตัวใหม่ทับเอง
- **ไฟล์ .zip** ที่ข้างในมี exe → ระบบแตก zip ทับให้เอง

## ถ้าอยากบังคับอัพเดต (ผู้เล่นกดข้ามไม่ได้)

ใน GitHub Release description ใส่คำว่า `[FORCE]` ไว้ในหัวข้อ — ตัว launcher จะบังคับอัพเดตก่อนใช้งานได้
(ตรวจรายละเอียดพฤติกรรมจริงได้ที่ฟังก์ชัน `check_for_updates` ใน `launcher/launcher_core/updater.py`)

## จำเป็นไหมว่าต้องเปิด source บน GitHub?

ไม่จำเป็น สามารถใช้ Releases อย่างเดียวได้ (repo เป็นสาธารณะแต่ไม่ใส่โค้ดก็ได้)
ที่สำคัญคือ tag + ไฟล์แนบในหน้า Releases ต่างหาก
